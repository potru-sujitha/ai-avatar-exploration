# Open-Source End-to-End Photo-to-Rigged-3D-Head Pipelines

## 1. Are there open-source "digital human"/"talking head"/VTuber toolkits that cover photo-to-avatar AND output GLB-compatible rigged meshes?

### Takeaway
No actively-maintained, popular open-source toolkit was found that takes a single photo in and outputs a GLB/glTF head with ARKit or Oculus blendshapes as a packaged, documented product. The closest things found are (a) tiny, barely-starred community glue projects that chain several academic repos together manually, and (b) a real-time facial-mocap SDK (not a photo-to-mesh generator) that is archived and not fully open source.

### Cited Findings
- **ujjawalcse/3D-Virtual-Avatar** (GitHub, MIT license, 1 star / 0 forks) is the single most on-target "chained pipeline" project found. Its README describes: single photo/video → PIXIE+DECA for full-body reconstruction with facial detail → DECA (with SPECTRE/EMOCA tried for better expressiveness) for the face mesh up to the neck in FLAME topology → merging face with a rigged clothed body → blendshapes generated via NVIDIA Omniverse Audio2Face → Neural Blend Shapes for skinning → Blender `bpy` scripts exporting to "AR/VR suitable file format like .FBX/.GLB." — [github.com/ujjawalcse/3D-Virtual-Avatar](https://github.com/ujjawalcse/3D-Virtual-Avatar)
  - It does not mention ARKit/Oculus-named blendshapes specifically (blendshapes come from Audio2Face's own naming scheme), does not state whether output is realistic or stylized, gives no GPU requirements, and shows no visible last-update date (only 3 commits, 1 star) — effectively an unmaintained personal proof-of-concept, not a toolkit with documentation or community adoption.
- **facemoji/mocap4face** — a free, cross-platform real-time facial motion-capture SDK (FACS-based) that outputs ARKit-style blendshapes from photos or video, head position and scale. ~612 stars / 113 forks, but the GitHub repo was **archived by the owner on 2022-11-29** and is licensed under a proprietary "Facemoji SDK License Agreement" (not a standard OSI license), with a separate license for sample code — [github.com/facemoji](https://github.com/facemoji), [gittrend.io/repo/facemoji/mocap4face](https://gittrend.io/repo/facemoji/mocap4face). This is mocap (driving existing blendshapes from a live face), not single-photo-to-personalized-mesh generation, and is no longer actively maintained.
- **SpookyCorgi/phiz** — an open-source (GPLv3) in-browser facial motion-capture tool using ARKit-compatible blendshapes, offered as a free alternative now that mocap4face is archived. Also a live-mocap tool, not a photo-to-avatar reconstruction pipeline — [relatedrepos.com/gh/facemoji/mocap4face](https://relatedrepos.com/gh/facemoji/mocap4face) (citing Phiz as the alternative).
- **digitalp/arkit-blendshape-tool** — copies the 52 ARKit blendshapes and 15 Oculus visemes from a reference GLB that already has them onto a target GLB that lacks them (CLI + web UI), injecting real glTF morph targets. It requires both meshes to have similar face geometry and a reference avatar that already has the blendshapes — it does not create a mesh from a photo at all, it only transplants blendshapes onto a mesh you already have. ~1 star, no license stated in the page fetched — [github.com/digitalp/arkit-blendshape-tool](https://github.com/digitalp/arkit-blendshape-tool).
- VRoid/VRM-style pipelines: no evidence was found that VRoid Studio or the VRM ecosystem supports single-photo-driven *realistic* head generation — VRoid is a manual, anime/stylized character modeler, and no search turned up a photo-import or photo-texture feature for realistic faces. This is a **gap** (not confirmed either way with a primary source) rather than a confirmed "no."

### Inferences
- The "toolkit" layer (digital-human SDKs, VTuber avatar makers) is dominated by commercial/hosted products (Avatar SDK/MetaPerson, KeenTools, Meshy, Avaturn) which are explicitly out of scope here; the open-source side of this space consists mostly of (1) academic reconstruction repos, (2) live-mocap/blendshape-driving SDKs (which assume you already have a rigged mesh), and (3) small individual glue projects stitching the two together with no packaging or support.
- Community adoption signal (stars/forks/issue activity) for every genuinely open-source candidate found is very low (low hundreds of stars at best for mocap4face, which is archived; 1–30 stars for the actual photo→rig→export glue projects), confirming this is not a mature, widely-adopted category yet.

### Gaps
- Could not confirm or deny whether VRoid/VRM tooling has any realistic (non-anime) single-photo mode — no primary source found; would need to check VRoid Hub/Pixiv documentation directly.
- Could not verify ujjawalcse/3D-Virtual-Avatar's last commit date or whether the Blender export script runs end-to-end without manual intervention; the README reads as a personal experiment log rather than a tested pipeline.

## 2. Academic repos that explicitly advertise a full pipeline (photo → rigged mesh → export), e.g. FLAME/DECA-based with added rigging+export stage

### Takeaway
DECA and its descendants (EMOCA, SPECTRE) are the de facto standard open-source single-photo face reconstruction backbone, but **none of the official repos export glTF/GLB or ARKit/Oculus blendshapes themselves** — they output FLAME parameters / OBJ meshes only, and all carry non-commercial research-only licenses. ROME (SamsungLabs) is the clearest academic repo that explicitly claims a "photo → rigged, renderable head avatar" pipeline with public code, but its "rig" is a neural rendering network, not a standard skinned glTF mesh with blendshapes, and it also requires DECA+FLAME as dependencies under the same non-commercial terms.

### Cited Findings
- **yfeng95/DECA** (~2.5k stars, 44 commits visible) — "reconstructs a 3D head model with detailed facial geometry from a single input image," with aligned reconstruction and animation via expression transfer from other images shown in the README. Output is an OBJ mesh (openable in Meshlab) with extracted texture — no glTF/GLB or FBX export is mentioned anywhere in the README. License: "available for non-commercial scientific research purposes as defined in the LICENSE file" (exact OSI license name not stated in the LICENSE text itself as fetched — it's a custom non-commercial research license, not MIT/Apache/BSD). Requires Python 3.7, PyTorch ≥1.6, optional pytorch3d; no explicit GPU spec given in the README. The FLAME model it depends on is a separate download with its own license — [github.com/yfeng95/DECA](https://github.com/yfeng95/DECA).
- **FLAME model itself**: per the FLAME-Universe meta-repo, FLAME is "publicly available under Creative Commons Attribution license," which — unlike DECA/EMOCA's own code licenses — does in principle permit commercial use, though this should be verified against the exact license text served with each FLAME download, since different FLAME-related assets (e.g., the Basel Face Model-derived albedo/texture space) carry different and more restrictive terms — [github.com/TimoBolkart/FLAME-Universe](https://github.com/TimoBolkart/FLAME-Universe).
- **radekd91/emoca (EMOCA)** — extends DECA for more emotionally expressive reconstruction/animation. Its repo states the "code and model are available for non-commercial scientific research purposes as defined in the LICENSE file" — same non-commercial restriction as DECA. A fork notes EMOCA's authors "are not allowed to distribute the texture space" (Basel Face Model-derived), so users must separately obtain and convert BFM themselves — [github.com/radekd91/emoca](https://github.com/radekd91/emoca).
- **SPECTRE** (filby89/spectre) — used by other projects (e.g., SGNify, and informally by ujjawalcse/3D-Virtual-Avatar) for better facial expression capture on top of FLAME, but no license text for SPECTRE itself was confirmed in search results; a related project (SGNify) that consumes SPECTRE output is licensed non-commercial research-only — [relatedrepos.com/gh/filby89/spectre](https://relatedrepos.com/gh/filby89/spectre).
- **SamsungLabs/rome (ROME — "Realistic One-shot Mesh-based Head Avatars," ECCV 2022)** — official inference code is public. From a single photograph, "the system estimates the head mesh, along with a neural texture, and the resulting avatars are rigged and can be rendered using a deep rendering network." Requires the FLAME model and pretrained DECA weights to run (`python3 infer.py --deca DECA --rome data`). License: "code and model are available for scientific research purposes as defined in the LICENSE file" (non-commercial). No mention anywhere of glTF/GLB/FBX export or ARKit/Oculus blendshape naming — the "rig" drives a neural renderer, not a standard glTF skeletal/morph-target rig, so it is **not verified** to produce anything GLB-importable without substantial additional engineering — [github.com/SamsungLabs/rome](https://github.com/SamsungLabs/rome) (also mirrored at [huggingface.co/Pie31415/rome](https://huggingface.co/Pie31415/rome)).
- **Tencent-AILab HiFi3DFace** — claimed in search snippets to build "a full head rig" from a consumer RGB-D selfie **video** (not a single static photo) in under 30 seconds, described as "a fully automatic pipeline." However, the repo page itself returned HTTP 404 on direct fetch during this research, so its current license, export format, blendshape support, GPU requirements, and maintenance status could **not be verified directly** and should be treated as unconfirmed secondary-source information only — [search snippet citing tencent-ailab/hifi3dface, not independently verified].
- **ROME's own input requirement**: single photo is confirmed by the paper abstract and repo description itself, unlike HiFi3DFace which explicitly needs RGB-D *video*.

### Inferences
- There is a consistent, repeated licensing pattern across this entire academic lineage (DECA → EMOCA → SPECTRE-consuming projects → ROME): code and pretrained weights are released for **non-commercial scientific research only**, while the underlying FLAME parametric model itself is more permissively licensed (CC-BY) — meaning commercial use of any DECA/EMOCA/ROME-based pipeline would likely require separate licensing negotiation with the original authors even if you could legally use bare FLAME.
- None of these academic repos treat glTF/GLB export or ARKit/Oculus blendshape conformance as an in-scope deliverable — that conversion/rigging work is left entirely to downstream users, which is exactly the gap that small community glue-projects (like ujjawalcse/3D-Virtual-Avatar) are informally trying to fill, with very limited success/maturity so far.

### Gaps
- Could not independently verify HiFi3DFace's repo content (404 on fetch) — all claims about it are secondhand from search snippets and should be re-verified before being presented as fact.
- Could not find an EMOCA or SPECTRE successor (e.g., a 2024-2026 release) that adds native glTF/blendshape export — this remains unconfirmed; worth a follow-up search specifically for "EMOCA 2025 glTF export" or newer FLAME-based toolchains if more research time is available.
- No GPU hardware specifics (e.g., VRAM figures) were stated in any of the DECA/EMOCA/ROME README content fetched.

## 3. Is there an open-source project explicitly positioned as a "self-hosted Ready Player Me alternative" or "open-source MetaHuman alternative"?

### Takeaway
No genuinely open-source, photo-driven, self-hostable project explicitly marketed with that framing was found. The nearest things to "open-source RPM-style avatar creator" are stylized/preset-based character customizers (not photo reconstruction) that are old and largely unmaintained; everything that explicitly uses "MetaHuman alternative" framing in search results is a paid commercial product.

### Cited Findings
- **AtlasFoundation/AvatarCreator** (aka "NEAR Open Character Creator" after apparent renaming/forking) is described by the M3 community's own dev log as "the closest thing we have to open source Ready Player Me style character creation" — "An open, collaborative and evolving 3D avatar creator and optimizer for the open metaverse." A third-party aggregator lists it at roughly 30 stars, last updated January 2023 (so likely unmaintained as of this research date, 2026-11-06). It is a preset/morph-based VRM-style avatar assembler (clothing, body morphs), not a single-photo reconstruction tool, and a README excerpt notes multi-material download isn't even supported — [github.com/AtlasFoundation/AvatarCreator](https://github.com/AtlasFoundation/AvatarCreator) (per [hackmd.io/@XR/avatarbuilders](https://hackmd.io/@XR/avatarbuilders) dev log), related lineage at [m3-org.github.io/characterstudio-docs/docs/history](https://m3-org.github.io/characterstudio-docs/docs/history).
- **m3-org/ready-player-m3** — named directly in the same M3 dev log as a related open-source project, said to support headless avatar use; no further verified detail (license, photo support, export format) was obtained in this research pass — gap, flagged below.
- **MakeHuman** — repeatedly surfaces in search results as "the best open-source Ready Player Me / MetaHuman alternative," and is genuinely free and open source. However, it is a **manual** desktop morph-based character modeler (sliders for body/face shape), not a photo-driven reconstruction tool, so it does not fit the "single photo in" requirement at all.
- For "MetaHuman alternative" framing specifically, every concrete product that used that exact phrase in search results was commercial/hosted and explicitly out of scope per the task's exclusion list: MetaPerson/Avatar SDK (commercial, cloud-or-on-premise, selfie→GLB/FBX with 51 "mobile" blendshapes + 15 visemes), Meshy (hosted, full-body not head-focused), and KeenTools FaceBuilder/cloud API (commercial REST API, MetaHuman-topology output). None of these were found to have an open-source self-hostable core — they are commercial products even where an "on-premise"/"Local Compute" tier is marketed by secondary resellers.
- Epic's own **MetaHuman DNA Calibration** library is open-sourced by Epic, but it is a rigging/puppeteering calibration toolkit for already-built MetaHuman rigs — it is not a photo-to-avatar generator and was not the subject of a direct fetch in this pass (flagged as a gap, not confirmed further).

### Inferences
- The "self-hosted RPM/MetaHuman alternative" framing that the task asked to search for directly does not appear to have produced a serious, actively-maintained open-source candidate — the phrase mostly attracts marketing copy from commercial competitors (Genies, Avatar SDK, Meshy) rather than genuine open-source projects describing themselves that way.
- Preset/morph-based avatar creators (MakeHuman, AtlasFoundation/AvatarCreator) solve a different problem (customizable stylized/generic avatars) than "reconstruct *this specific person's* face from *their* photo," which is the core ask here — so even the best "RPM-adjacent" open-source tools don't actually address the photo-input requirement.

### Gaps
- m3-org/ready-player-m3's license, photo-input capability, and export/blendshape support were not verified — would need a direct repo fetch.
- MetaHuman DNA Calibration's exact scope and license were not independently verified in this pass.

## 4. Realistic assessment: does any single open-source repo do the full pipeline well, or does every real implementation require manually combining separate repos?

### Takeaway
Based on everything found, as of November 2026 there is **no single open-source repository that does single-photo → rigged, animatable, ARKit/Oculus-blendshape GLB export well, with documentation and real community adoption.** Every real-world-usable path currently requires manually combining (at minimum) a reconstruction repo, a separate rigging/blendshape step, and a separate export/conversion script — exactly the fragmented workflow the task asked to confirm or deny. The one project found that explicitly tries to be that single chained pipeline (ujjawalcse/3D-Virtual-Avatar) is a personal proof-of-concept with 1 GitHub star and no confirmed maintenance activity, not a usable product.

### Cited Findings
- Every reconstruction-quality candidate (DECA, EMOCA, SPECTRE, ROME) stops at a mesh/parameter/OBJ output or a neural-rendering "rig" — none natively emits glTF/GLB or ARKit/Oculus-named blendshapes. This was confirmed directly from each repo's own README/LICENSE content fetched above, not inferred.
- Every genuinely GLB/blendshape-aware open-source tool found (arkit-blendshape-tool, FaceIt Blender add-on, mocap4face/Phiz) assumes you already have a rigged mesh and is solely about applying/transferring/driving blendshapes on top of it — none does photo-to-mesh reconstruction.
- The only project that attempts the full chain end-to-end (ujjawalcse/3D-Virtual-Avatar: DECA/PIXIE → FLAME-topology face → Audio2Face blendshapes → Neural Blend Shapes skinning → Blender `bpy` → FBX/GLB) is explicitly a stitched-together combination of at least six different upstream research/commercial-tool components (PIXIE, DECA, SPECTRE/EMOCA, VOCA/FaceFormer, NVIDIA Omniverse Audio2Face, Neural Blend Shapes, ROMP, Blender), which itself is strong direct evidence for "fragmentation is the norm, not the exception" — this is not a counter-example to that conclusion, it's confirmation of it, since the glue code has essentially no adoption (1 star, 0 forks) and NVIDIA Omniverse Audio2Face is itself a separate large proprietary-adjacent dependency, not part of a clean open pipeline.
- Licensing compounds the fragmentation problem: even if someone successfully chained DECA (non-commercial) → FLAME (CC-BY, more permissive) → EMOCA/SPECTRE (non-commercial) → a blendshape tool (license frequently unstated, e.g. arkit-blendshape-tool) → Blender export, the resulting pipeline would likely be legally restricted to non-commercial use by its most restrictive component, even though no single README says "you cannot use this commercially" for the assembled whole.

### Inferences
- The practical conclusion for this research question is: **yes, every real-world implementation currently requires manually combining a reconstruction repo + a separate rigging/blendshape step + a separate export/conversion step**, and in practice usually more than three components (the one "integrated" example found used roughly six to eight upstream projects). No maintained, documented, community-adopted single repo closes this gap as of this research date.
- Given the strength and recency of commercial offerings found during this research (Avatar SDK/MetaPerson, Meshy, KeenTools) that do solve "single selfie → rigged GLB with ARKit-style blendshapes" cleanly, the market gap for an open-source equivalent appears to be a deliberate/economic one (these pipelines require nontrivial proprietary ML models and texture-space data such as licensed face-scan datasets), not simply an oversight — none of the restrictive licenses found (DECA, EMOCA, ROME) were incidental; they consistently trace back to restrictions on the underlying face-scan/texture training data (e.g., Basel Face Model) that the academic authors do not have rights to relicense permissively.

### Gaps
- This research did not exhaustively check every possible 2025-2026 academic release (e.g., very recent Gaussian-splatting-based head avatar papers such as GaussianAvatars, Avat3r, or F3G-Avatar were surfaced only by title/abstract in search snippets and not fetched/verified for license, single-photo support, or GLB export — they appear to require multi-view/video input for training rather than a single photo, based on snippet descriptions, but this is not independently confirmed).
- No first-hand Reddit/HN/dev.to 2024-2026 practitioner discussion threads specifically describing hands-on attempts at self-hosted realistic photo-to-rigged-GLB pipelines were found in this research pass (search queries for this returned only commercial-product marketing pages and the same GitHub repos already covered) — this is a gap in the "practical real-world experience reports" source type the task requested; a follow-up search focused on specific subreddits (r/blender, r/MachineLearning, r/VirtualReality) or Hacker News "Ask HN" threads by name could help close it.
